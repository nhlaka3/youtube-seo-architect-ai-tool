2. TECH STACK & WHY EACH TOOL
============================================================

BACKEND:
  Express.js v5      — HTTP framework (chosen over Fastify
                        for ecosystem maturity and middleware)
  Node.js 20         — Runtime (ES modules with "type": "module")
  PostgreSQL (Neon)  — Serverless Postgres (chosen over MongoDB
                        because structured relational data:
                        users, transactions, logs, trials)
  Drizzle ORM        — Type-safe SQL ORM (chosen over Prisma
                        because: lighter, faster cold starts,
                        no binary engine, better for serverless)
  Zod                — Runtime validation (schemas for every
                        request body and query parameter)

AI:
  Groq SDK           — Primary LLM (llama-3.1-8b-instant)
                        Fast inference, low cost, JSON mode
  Google Gemini      — Failover LLM (gemini-2.0-flash)
                        Used when Groq fails or is rate-limited
  Multi-Brain System — Try Groq first, fall back to Gemini,
                        with retry logic (max 2 retries)

SECURITY:
  Helmet             — HTTP security headers (HSTS, CSP, etc.)
  CORS               — Origin whitelist (only your domain + localhost)
  CSRF               — Token-based protection (HMAC-SHA256)
  Rate Limiting      — 500 req/15min global, 10 req/min for AI
  Input Sanitization — Strip prompt injection attempts
  Zod Validation     — Every request body validated before processing

MONITORING:
  Sentry             — Error tracking with breadcrumbs
  Winston            — Structured logging with rotation
  Performance MW     — Request duration tracking

DEPLOYMENT:
  Vercel             — Serverless functions (auto-scales)
  Neon               — Serverless PostgreSQL (scales to zero)
  Git                — Version control

3. BACKEND ARCHITECTURE (api/index.js)
============================================================

The entry point (api/index.js) sets up everything:

IMPORT ORDER MATTERS:
  1. dotenv/config — loads .env variables FIRST
  2. Sentry init — must be before any other imports
  3. Express app creation
  4. Middleware stack (in exact order)
  5. Route mounting

MIDDLEWARE STACK (in order):
  ┌─────────────────────────────────────────┐
  │ 1. Sentry Request Handler (captures all)│
  │ 2. Sentry Tracing Handler               │
  │ 3. Helmet (security headers)            │
  │ 4. CORS (origin validation)             │
  │ 5. express.json (body parsing, 1mb max) │
  │ 6. Input Sanitization (anti-injection)  │
  │ 7. Performance Middleware                │
  │ 8. Request Logger (Winston + Sentry)    │
  │ 9. Rate Limiter (500/15min)             │
  │ 10. Routes                              │
  └─────────────────────────────────────────┘

ENVIRONMENT VALIDATION:
  - Checks for GROQ_API_KEY, CSRF_SECRET at startup
  - In production: also checks PAYPAL_*, DATABASE_URL
  - If CSRF_SECRET is default value in production → EXIT
  - Missing vars don't crash serverless (marks config invalid)

ERROR HANDLING:
  process.on('uncaughtException') → log + exit(1)
  process.on('unhandledRejection') → log only (don't crash)
  Route-level try/catch in every handler

5. AI INTEGRATION (Multi-Brain Provider)
============================================================

FILE: api/_lib/ai-provider.js

THE PATTERN:
  askAI(systemPrompt, userPrompt, options)
  ├── Try Groq (llama-3.1-8b-instant)
  │   └── Success → return result
  │   └── Fail → try Gemini
  ├── Try Gemini (gemini-2.0-flash)
  │   └── Success → return result
  │   └── Fail → retry with backoff
  └── After 3 attempts → throw error (or mock in dev)

WHY THIS PATTERN:
  - Groq is fast (8b model) and cheap
  - Gemini is more capable but slower
  - Failover ensures high availability
  - Retry with exponential backoff handles transient errors

JSON PARSING:
  - AI often returns markdown-wrapped JSON (```json...```)
  - parseAIJson() handles: strip fences → extract object → parse
  - Multiple fallback attempts: direct parse → fix common issues
    (trailing commas, unquoted keys) → normalize newlines

CHAIN-OF-THOUGHT:
  - When forceJson is true, appends reasoning array to prompt
  - Forces LLM to think step-by-step before outputting JSON
  - Example: {"reasoning":["step1","step2","step3"], ...}

COST TRACKING:
  - Rough estimation: Groq ~$0.0002/1K tokens, Gemini ~$0.0005/1K
  - Tracks: totalCost, totalCalls, costByProvider
  - Exposed via getAICostStats() for monitoring

PROMPT SANITIZATION:
  sanitizePromptInput() strips:
  - Prompt injection attempts ("ignore previous instructions")
  - Jailbreak keywords ("dan", "uncensored")
  - Control characters and newlines
  - Caps to maxLen (500 default)

6. SECURITY LAYER
============================================================

--- Helmet (HTTP Security Headers) ---
  - Content Security Policy (CSP): whitelist of allowed sources
  - HSTS: 1 year max-age, includeSubDomains, preload
  - Cross-Origin policies configured for PayPal/Google integrations

--- CORS ---
  - Only allows: yt-seo-architect.vercel.app + *.vercel.app
  - In development: localhost and 127.0.0.1
  - Credentials: true (for auth cookies)
  - Allowed methods: GET, POST, PUT, DELETE
  - Max age: 24 hours (86400s)

--- CSRF Protection ---
  - Token = HMAC-SHA256(secret, sessionId:timestamp)
  - Tokens expire after 1 hour
  - Uses timingSafeEqual to prevent timing attacks
  - Currently disabled (100% free tool, no payments)

--- Rate Limiting ---
  - Global: 500 requests per 15 minutes per IP
  - AI endpoints: 10 requests per minute per channel
  - Returns 429 with retry-after header

--- Input Validation ---
  - Every POST body validated with Zod schemas
  - Types enforced: string, number, array, object
  - Required fields checked
  - Pattern matching: channelId must match /^UC[\w-]{22}$/

--- Prompt Injection Defense ---
  - Global middleware sanitizes: topic, q, query, seed, keyword,
    prompt, userPrompt, systemPrompt
  - Strips: "ignore previous instructions", jailbreak keywords,
    control characters, excessive length

--- Serverless Security ---
  - CSRF_SECRET must not be default value in production
  - Missing env vars don't crash (marks config invalid)
  - Sentry captures errors but doesn't expose internals

8. AUTONOMOUS AGENT SYSTEM
============================================================

This is the most impressive part of your project.
It's a multi-agent AI system that runs automatically.

--- Agent Architecture ---

  ┌─────────────────────────────────────┐
  │         ORCHESTRATOR                 │
  │  (api/agent-workflows/orchestrator) │
  │  - Coordinates all sub-agents       │
  │  - Enforces daily limits            │
  │  - Circuit breaker (error rate)     │
  │  - Concurrency guard                │
  └──────────┬──────────────────────────┘
             │
  ┌──────────┴──────────────────────────┐
  │         SUB-AGENTS                  │
  │                                     │
  │  Scanner    — scans videos for SEO │
  │  Optimizer  — proposes fixes        │
  │  Trend      — detects trends        │
  │  A/B Test   — runs experiments      │
  │  Coach      — learns from outcomes  │
  │  Content    — plans new content     │
  │  PSEO       — generates blog posts  │
  └─────────────────────────────────────┘

--- Goal Engine (api/agent-core/goal-engine.js) ---

  setGoal(channelId, type, target, deadline)
  ├── Gets current metric (subs/views/watch_hours)
  ├── Generates plan with phases:
  │   Phase 1: AUDIT (establish baseline)
  │   Phase 2: OPTIMIZE (immediate wins)
  │   Phase 3: GROWTH (scale what works)
  │   Phase 4: COMPOUND (compound effects)
  ├── Persists to PostgreSQL
  └── Returns goal with progress tracking

  getGoalStatus(channelId)
  ├── Calculates weekly growth rate
  ├── Projects ETA based on current velocity
  └── Updates DB with current progress

--- Planner (api/agent-core/planner.js) ---

  generatePlan(goalId, goalText, niche)
  ├── Creates dependency-aware action sequence
  ├── Steps have: agent, action, dependency, rationale
  ├── Expected outcomes for each step
  └── Adapts based on goal type:
      - Subscriber goals → focus on CTR optimization
      - View goals → focus on trends + SEO
      - CTR goals → focus on thumbnails + A/B testing

--- Scoring Engine (api/agent-core/scoring-engine.js) ---

  calculateExpectedValue(actionType, confidence, impact)
  ├── EV = (Confidence × Impact) - (Cost × RiskMultiplier)
  ├── Risk increases when:
  │   - Near API quota limits
  │   - Trend is volatile
  │   - User recently skipped similar actions
  │   - Sensitive action (title/thumbnail change)
  ├── Risk decreases when:
  │   - Historical win rate > 70%
  │   - Brand safety is low
  ├── Verdict: high_value / medium_value / low_value
  └── Threshold: EV > 0.5 to be queued

--- Concurrency Guard ---

  let _runToken = 0;
  let _runAbortController = null;

  function runAutonomousLoop() {
    const myToken = ++_runToken;
    if (_runAbortController) _runAbortController.abort();
    _runAbortController = new AbortController();
    // ... run with signal.aborted checks
  }

  WHY: Prevents overlapping cron/manual runs.
  Each new run aborts the previous one via AbortController.

--- Circuit Breaker ---

  Checks error rate across all agent actions
  If error rate > 15% → trips circuit → pauses all sub-agents
  Prevents cascading failures from broken API keys or quotas

--- Daily Limits ---

  Default: 10 optimizations per day
  Counts only "real" agents (not system/admin actions)
  Prevents runaway automation from burning API quota

9. SEO SCORING ALGORITHM
============================================================

FILE: api/youtube-ops.js — computeSEOScores()

This is a vidIQ-style 0-100 scoring system.

--- TITLE SCORING (0-100) ---
  Base: 30 points
  + 25  if length ≤ 60 chars (YouTube truncates at 60)
  + 8   if length 60-70 chars
  - 10  if length > 70 chars
  + 8   if front-loaded keyword (first 45 chars have 10+)
  + 8   if contains numbers
  + 6   if contains brackets: [ ] ( )
  + 3   if contains ! or ?
  + 10  if contains power words (how, why, secret, proven, etc.)
  - 8   if all-caps block > 15 chars
  - 5   if excessive punctuation (!!!, ???)

--- DESCRIPTION SCORING (0-100) ---
  Base: 20 points
  + 30  if word count ≥ 200
  + 20  if word count 150-199
  + 10  if word count 100-149
  + 5   if word count 50-99
  + 10  if character length ≥ 1500
  + 6   if character length 1000-1499
  + 5   if contains hashtags
  + 8   if contains CTA (subscribe, like, comment, etc.)
  + 5   if contains links
  + 10  if tags appear in description
  + 7   if contains timestamps (MM:SS pattern)

--- TAGS SCORING (0-100) ---
  Base: 15 points
  + 25  if tag count 10-25 (sweet spot)
  + 15  if tag count 5-30
  + 15  if NO tags contain spaces (YouTube treats them as separate)
  - (spaced_tags × 3) penalty for spaces
  + 15  if 5+ long-tail tags (3+ words)
  + 8   if 2+ long-tail tags
  - 10  if >60% are single-word tags (too generic)
  + 10  if total chars 200-500 (YouTube's 500 char limit)
  - 5   if total chars > 500
  - (duplicates × 3) penalty

--- OVERALL SCORE ---
  title × 0.35 + desc × 0.35 + tags × 0.30

12. INTERVIEW Q&A CHEAT SHEET
============================================================

Q: "Tell me about your project."
A: "I built YT SEO Architect, a full-stack AI platform for
    YouTube creators. It has 17 AI-powered tools including
    keyword research, metadata optimization, an autonomous
    agent system that runs SEO improvements automatically,
    and a conversational AI coach. It's deployed on Vercel
    with PostgreSQL, uses Groq and Gemini for AI inference,
    and is 100% free to use."

Q: "Why did you choose Express.js over Fastify or Koa?"
A: "Express has the largest middleware ecosystem and I needed
    specific middleware (Helmet, CORS, rate limiting) that
    integrates seamlessly. For a project with 30+ routes and
    complex middleware chains, Express's maturity and debugging
    tooling outweighed Fastify's raw performance."

Q: "Why Drizzle ORM over Prisma?"
A: "Three reasons: (1) No binary engine — Prisma bundles a
    Rust binary that adds cold start time on Vercel. Drizzle
    is pure JS. (2) Drizzle generates standard SQL — I can
    see exactly what queries run. (3) Drizzle is lighter
    (~200KB vs Prisma's ~5MB node_modules impact). For a
    serverless deployment where cold starts matter, this was
    critical."

Q: "How does your AI failover work?"
A: "I implemented a Multi-Brain pattern in ai-provider.js.
    Every AI call tries Groq first (fast, cheap, llama-3.1-8b),
    then falls back to Gemini (more capable, slower) if Groq
    fails. There's exponential backoff retry logic (max 2
    retries). In development, it falls back to mock responses.
    This ensures 99.9% uptime for AI features."

Q: "How do you prevent prompt injection?"
A: "Three layers: (1) Global middleware strips injection patterns
    from all POST bodies — catches 'ignore previous instructions',
    jailbreak keywords, and control characters. (2) sanitizePromptInput()
    in the AI engine strips remaining attacks. (3) Zod validation
    ensures input types and lengths are constrained before
    reaching AI prompts."

Q: "Explain your autonomous agent system."
A: "It's a multi-agent architecture with an orchestrator that
    coordinates specialized sub-agents: scanner (analyzes videos),
    optimizer (proposes fixes), trend scanner (detects trends),
    A/B tester (runs experiments), and a coach (learns from
    outcomes). It uses Expected Value scoring to prioritize
    actions — EV = (confidence × impact) - (cost × risk).
    There's a circuit breaker that pauses all agents if error
    rate exceeds 15%, and daily limits prevent runaway automation."

Q: "How does your scoring algorithm work?"
A: "I built a vidIQ-style 0-100 scoring system. Title scoring
    checks length (≤60 chars is ideal), power words, numbers,
    brackets. Description scoring checks word count (200+ is
    ideal), timestamps, CTAs, hashtags. Tags scoring checks
    count (10-25 sweet spot), long-tail coverage, duplicate
    detection, and whether tags have spaces (which YouTube
    splits into separate tags). Overall is a weighted average:
    35% title, 35% description, 30% tags."

Q: "How do you handle serverless cold starts?"
A: "Several strategies: (1) Drizzle ORM instead of Prisma
    (no binary to load). (2) Lazy-load Gemini only when needed
    (not on every request). (3) Dynamic imports for non-critical
    modules. (4) Deferred migrations (run on first request,
    not at startup). (5) No process.exit(1) for missing env
    vars — marks config invalid instead of crashing."

Q: "How do you ensure data consistency?"
A: "Atomic operations via Drizzle transactions. Idempotency
    keys on credit deductions prevent double-charging. The
    concurrency guard (AbortController) prevents overlapping
    agent runs from corrupting state. Circuit breaker prevents
    cascading failures."

Q: "What would you do differently?"
A: "I'd add Redis caching for YouTube API responses (rate
    limited to 10,000 units/day). I'd implement WebSocket
    for real-time agent status updates instead of polling.
    And I'd add comprehensive integration tests — currently
    I have API-level tests but not full E2E coverage."

Q: "How do you handle errors in production?"
A: "Sentry captures errors with full context (breadcrumbs,
    user info, request data). Winston logs structured JSON
    with rotation. Every route has try/catch that returns
    meaningful error messages without exposing internals.
    Circuit breaker pauses automation if error rate spikes.
    Uncaught exceptions log and exit; unhandled rejections
    log but don't crash the serverless function."
